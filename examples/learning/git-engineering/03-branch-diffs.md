> **生成演示内容**：本篇用于展示分章学习，不代表作者经历或生产实测。所有操作只针对你新建的练习目录；不要在真实业务仓库或服务器照抄。

## 先画出三份快照

假设主线已有文件 `plan.txt`，你从主线创建了一个实验分支。实验增加一条记录，主线也在另一个提交里增加说明。现在询问“这个分支改了什么”，可能是在问两个端点有何不同，也可能是在问实验分支从分叉以后引入了什么。

```text
A --- B       main
 \
  C --- D     experiment
```

下面两条命令只读取提交内容，不修改文件。前提是练习仓库已创建这两个分支；不存在时应先在沙箱构造提交，不要拿真实远端分支冒充练习。

```bash
git diff main experiment -- plan.txt
git diff main...experiment -- plan.txt
git log --oneline --graph --all
```

第一条比较主线与实验分支的端点，第二条以共同祖先为起点观察实验端点。它们回答不同问题，不能因为输出更短就认为其中一个“更正确”。在评审里，最关键的是说明比较基线，并让评审者能还原这个基线。

## 给阅读者一张地图

分支本身不是一份复制出来的完整目录，它指向一份提交。切换分支会改变当前检出的快照；未提交改动是否允许随切换保留，取决于它们与目标快照的关系。因此，练习前检查工作区状态，避免把分支理解成能够自动隔离所有未提交实验的抽屉。

处理一个较大的基础设施改动时，可以先写一份小的行为验证，再逐步修改实现。每个提交要能独立解释，不要求所有中间设计都永远保留，但应确保最终评审范围没有混入无关文件。涉及历史重写时，先确认是否与他人共享；本节只观察差异，不执行重写或强制推送。

## 验证你的解释

把上图抄到笔记里，分别标出两条差异命令的起点和终点。再在沙箱让主线与实验分支修改不同文件，观察两种输出。如果无法说清共同祖先是哪份提交，先回到提交图，而不是反复切换命令直到出现喜欢的结果。

三点比较的具体定义见 [Git diff 官方文档](https://git-scm.com/docs/git-diff)。本节不依赖任何托管平台的评审界面，也不需要联网。

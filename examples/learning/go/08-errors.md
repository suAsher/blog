## 本节目标

遇到无效输入时，返回原因而不是伪造一个正常结果。

## 错误是函数约定的一部分

假设要计算平均值。输入为空时，没有可以计算的平均数；返回零会让调用者无法分清“平均值真的是零”和“根本没有数据”。Go 常用额外的 `error` 返回值表达失败，让调用者必须在继续使用结果前作出选择。

```go
package main

import (
    "errors"
    "fmt"
)

func average(values []float64) (float64, error) {
    if len(values) == 0 {
        return 0, errors.New("没有可计算的数据")
    }
    sum := 0.0
    for _, value := range values {
        sum += value
    }
    return sum / float64(len(values)), nil
}

func main() {
    result, err := average([]float64{2, 4, 6})
    if err != nil {
        fmt.Println("计算失败：", err)
        return
    }
    fmt.Println(result)
}
```

## 分别走一次成功和失败路径

执行 `go run .`，正常输入应输出四。把参数改为 `nil` 或空切片后再次运行，应出现明确的失败提示，不再输出一个看似正常的平均值。`nil` 的 error 表示这次调用没有报告错误，检查它和检查结果数值是两件不同的事。

函数在失败时同时返回一个零值，只是为了满足返回类型；调用者不能忽略错误再把零值当成可信答案。不要为了让代码变短使用空标识符丢弃重要错误，尤其是文件写入、解码或网络操作的错误。

## 错误应该由合适的一层处理

计算函数不知道页面该怎样显示失败，也不知道是否应该重试，因此只返回原因。入口函数在这里选择打印并结束。真实服务可以把错误转成合适的响应，但不应把内部路径、密钥或原始请求全部展示给读者。

## 本节目标

区分输入无效、普通分支和默认分支。

## 从规则开始，而不是从语法开始

假设要根据练习完成数量给出一句反馈。这是一个构造的学习场景，不是实际考核制度。先写出规则：负数无效；零表示尚未开始；小于三表示正在推进；其余表示可以复习。确定条件范围后，再把它们翻译成代码，会比反复嵌套判断更清晰。

```go
package main

import "fmt"

func main() {
    completed := 2
    if completed < 0 {
        fmt.Println("完成数量不能为负数")
        return
    }
    switch {
    case completed == 0:
        fmt.Println("从第一步开始")
    case completed < 3:
        fmt.Println("保持节奏")
    default:
        fmt.Println("回顾一下学过的内容")
    }
}
```

## 检查分支是否覆盖边界

执行 `go run .`，当前应输出 `保持节奏`。依次把数量改为负一、零、二和三，每次运行观察命中的分支。这里使用不带表达式的 `switch`，每个 case 是一个条件。Go 默认只执行第一个匹配分支，不会像某些语言那样自动继续到后面的分支。

前面的 `return` 让无效数据在进入业务分支前离开函数，这种早返回通常能够减少嵌套层级。它并不是忽略错误：程序已经明确输出了无效原因。在真实接口或库函数里，应把错误返回给调用者，而不是只打印一行然后假装成功。

## 条件顺序也有意义

如果把“小于三”写在“等于零”之前，零也会先命中它。范围相互重叠时，较具体的条件应当先出现；如果规则很复杂，可以先用表格枚举输入和期望结果。不要为了视觉整齐把全部逻辑压成一条长表达式。

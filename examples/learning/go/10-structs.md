## 本节目标

用小模型描述文章，避免到处传递互不关联的变量。

## 数据之间有关系时，把关系写出来

标题、完成状态和预计时长共同描述一节课。把它们作为三个独立切片维护，很容易在排序或删除时失去对应关系。结构体把相关字段放在一个值里，让程序可以围绕“课程”这个概念表达行为。

```go
package main

import "fmt"

type Lesson struct {
    Title   string
    Minutes int
    Done    bool
}

func (lesson Lesson) Label() string {
    if lesson.Done {
        return lesson.Title + " · 已完成"
    }
    return lesson.Title + " · 待读"
}

func main() {
    lesson := Lesson{Title: "第一个程序", Minutes: 10}
    fmt.Println(lesson.Label())
    lesson.Done = true
    fmt.Println(lesson.Label())
}
```

## 从输出理解方法接收者

在学习模块执行 `go run .`，先看到待读，再看到已完成。`Label` 是定义在 Lesson 上的方法，接收者名字是 `lesson`。这里使用值接收者，方法观察这个值并返回文字，不负责修改原来的对象。真正的状态变化在 main 中明确发生。

字段名首字母大写表示可被其他包访问；它不代表自动持久化，也不会自动把数据暴露到网络。是否序列化和怎样校验输入，需要另外定义。方法的可见性也遵循同样的命名规则。

## 保持模型比界面更稳定

结构体里保存事实，而不是混入颜色、按钮位置等界面细节。`Minutes` 在演示中是构造值，不能当作可靠的学习耗时预测。若未来文章标题发生变化，应使用稳定 ID 关联阅读状态，而不是依赖可变标题充当唯一标识。

## 小练习

创建两节课程的切片，遍历并输出各自标签，再计算已完成数量。思考 Minutes 为零和负数时应该怎样处理：结构体本身不会阻止无效值，仍然需要在数据进入系统时校验。不要因为有了类型定义，就认为业务规则已经完整实现。

## 本节目标

区别计算精度和文字编码，避免看似合理的隐式假设。

## 类型不仅决定占多少内存

整数适合表示次数和索引，浮点数适合近似连续量，字符串适合保存不可变的字节序列。类型之间通常需要显式转换，编译器不会任意替你决定数据丢失是否可以接受。先问数据的含义，再选择表示方式，而不是把所有数字都改成浮点数。

```go
package main

import "fmt"

func main() {
    completed, total := 2, 3
    integerRatio := completed / total
    ratio := float64(completed) / float64(total)
    title := "学习Go"
    fmt.Println(integerRatio)
    fmt.Printf("%.2f\n", ratio)
    fmt.Println(len(title), len([]rune(title)))
}
```

## 先预测，再运行

在学习模块中执行 `go run .`。整数除法输出 `0`，转换后以两位小数显示约 `0.67`。显示位数不等于数据内部只有两位精度；`Printf` 在这里调整的是呈现方式。直接拿两个近似浮点结果做精确相等判断，可能不符合业务意图。

最后一行输出 `8 4`。`len` 对字符串计算字节数；转换成 rune 切片后统计 Unicode 码点数。一个中文汉字通常不是一个字节。码点数也不总等于人眼看到的字符数，组合音标和表情序列可能由多个码点组成。本例只为建立编码意识，不是完整的文本排版算法。

## 避免丢失发生在转换之前

`float64(completed / total)` 仍然得到零，因为括号里的整数除法已经完成。应当先转换参与计算的值，再执行除法。这个差异提醒我们：表达式的求值顺序和类型一起决定结果，而不仅是最后接收它的变量。

## 小练习与边界

把总数改成零会发生什么？先不要运行到处复用的工具函数，试着在计算前判断分母，并给出明确提示。将标题替换成包含表情的文本，再比较字节与码点数量。涉及金额时，不要直接把本节的浮点例子用于结算；应根据最小货币单位和业务舍入规则另行设计。

## 本节目标

用明确的名字表达数据，并看懂值何时可以改变。

## 名字是写给未来读者的

变量把一个名字和一个有类型的值关联起来。`var` 可以显式写类型，也可以让编译器根据初始值推断类型；函数内部还可以用 `:=` 声明新变量。先选择意思清楚的名字，比缩短一两个字符更重要。`retryCount` 比没有上下文的 `n` 更容易被理解。

```go
package main

import "fmt"

const maxRetries = 3

func main() {
    var completed bool
    retryCount := 0
    retryCount = retryCount + 1
    completed = retryCount <= maxRetries
    fmt.Printf("尝试 %d 次，允许继续：%t\n", retryCount, completed)
}
```

## 运行并解释结果

在已有学习模块中把代码保存到 `main.go`，执行 `go run .`，应看到尝试次数为 `1`，布尔值为 `true`。未显式赋值的布尔变量初始值为 `false`；数值的零值为零，字符串的零值为空串。零值让数据可以被确定地初始化，但不保证它就是业务上的合法值。

常量用于编译期可确定的值。上面的最大次数没有变化的需求，所以用 `const` 表达这个约束。把它改写成随意可变的全局变量，会增加理解程序状态的负担。反过来，来自用户输入的数量就不能声明成编译期常量。

## 留意花括号的边界

变量只能在自己的作用域内使用。函数内声明的变量不会自动出现在另一个函数中。在内层块使用 `:=` 时，可能声明一个遮蔽外层同名变量的新变量；这不是给外层变量赋值。遇到数值好像没有改变，先观察声明符号和花括号位置。

## 自己做一次修改

把重试次数增加到四，解释为什么布尔结果变成 `false`。再尝试给常量赋新值，记录编译器怎样拒绝它，最后恢复可运行状态。不要为了通过编译而随意删掉类型或约束；错误往往提醒你，当前表达方式和数据变化的意图并不一致。

## 这一节不承诺什么

变量名不会自动校验外部输入，零值也不是错误处理方案。后面写函数时，仍需把无效数据作为明确的返回结果处理，而不是让一个难以区分的零悄悄流入后续计算。

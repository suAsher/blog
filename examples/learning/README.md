## 建议阅读方式

刚开始编程，可先读 Go 或 Python 的起步章节，再补 Linux 与网络。已有编程经验，可直接从 Git、容器、性能或分布式系统的具体问题进入。AI 推理方向假设读者愿意理解请求、内存和延迟的基本概念，不需要真实 GPU、下载模型或付费 API。

对基础资料的阅读不需要一条固定流水线。遇到不懂的概念可以沿文章底部的知识链接回查，用批注留下问题，用专题对照不同文章。已读状态代表阅读记录，不代表掌握程度。

## 导入与维护

每个方向的 `index.json` 保存章和文章顺序。正文是可直接导入的 Markdown；辅助 JSON 和 README 不需要上传成文章。你可在页面「路线 → 新建方向」创建自己的课程，加入已经发布或正在写作的文档，调整章节标题和顺序。正文更新仍通过原来的草稿与发布快照机制。

`deploy/seed-learning-catalog.py` 只导入明确列出的七个新增演示方向，不修改已有 Go 路线或用户文章。每方向使用独立私有标记和稳定的导入收据，中断后重试不重复创建；已完成导入再次运行不会覆盖人工编辑。服务器凭据和会话只在服务器内部使用。

```bash
# 只校验源文件，不登录、不写入空间
python3 deploy/seed-learning-catalog.py --examples-root examples/learning --dry-run

# 单方向校验
python3 deploy/seed-learning-catalog.py --examples-root examples/learning --direction python --dry-run
```

服务器写入须明确提供 `--server-root /srv/asher-knowledge`；完整数据备份应包含 content/ 和 showcases/，后者用于安全重试。不要删除导入标记来强行重建示例。删除路线不会删除文章；如果不需要这些内容，可在空间中移除路线，再把对应演示文章移入回收站。

## 验证边界

Python 和 Git 的隔离练习、数值模型均可在临时目录中运行，不读取真实工作文档。分布式和推理例子是确定性的教学模拟，不能当作生产实现或性能测量。Linux 专用命令、Docker 构建与部署须按文章条件在相应环境验证；没有执行的步骤不算通过。应用的核心阅读和搜索不依赖这些外部工具或任何在线资料链接。

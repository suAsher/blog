## 先说清楚哪个进程在运行

镜像可以理解为程序文件与默认运行配置的组合，容器则是用这些材料启动的一次隔离执行。镜像存在，并不意味着服务已经监听端口；容器创建成功，也不意味着业务初始化完成。先明确运行的主进程，才能理解为什么某些容器会立刻退出。

```text
镜像：文件系统内容 + 默认入口与参数
运行配置：资源、用户、挂载、网络
容器：上述条件下启动的进程实例
```

下面是一个命令结构示意，`LOCAL_IMAGE` 必须替换成你已构建并检查过的本地镜像，不是一个可拉取的公共镜像名。不要原样执行占位符，也不要为了练习自动下载陌生镜像。

```bash
docker run --rm --name learning-once LOCAL_IMAGE command argument
```

如果入口只是输出一句话然后正常结束，容器退出就是预期行为。若它应该持续提供服务，则要检查进程为何退出、使用了哪些参数、输出了什么错误。增加自动重启只能重复失败，不能修复错误配置。

## 保存运行条件比记住名字更有用

两个容器即使用同一个镜像，只要参数、用户或挂载不同，行为就可能不同。排查时分别记录镜像身份、入口、资源限制、退出状态和启动日志。容器名是定位线索，不是完整的运行证明；名称复用以后，它甚至可能指向另一个实例。

对AI服务而言，模型文件是否存在、设备是否可访问、初始化是否完成，也都属于独立条件。不要用容器列表中的一个状态替代模型能够完成请求的证据。把探针分层设计，才能知道失败发生在程序启动还是业务就绪阶段。

## 用一个目录表达构建边界

准备一个全新的练习目录，只放需要发布的公开静态文件。下面的树是建议结构，不要求复制任何工作项目、密钥或真实文档进去。

```text
learning-image/
  Dockerfile
  .dockerignore
  site/
    index.html
```

在该目录执行 `docker build` 时，所选上下文决定构建器能够访问哪些文件。`COPY` 不是任意读取电脑文件的指令；它受上下文和其他显式输入约束。把庞大的上级目录当作上下文，会让输入范围难以审查，也可能带入本不属于产物的内容。

```text
# .dockerignore：教学示例
.git
.env
.env.*
secrets/
node_modules/
*.pem
```

这些规则只是防线之一，不能替代主动选择干净的构建目录。尤其不要把秘密先写入镜像一层，再指望后续删除后就等同于从未进入产物。构建凭据应按构建工具的专用机制管理，本篇不传入任何凭据。

## 让缓存围绕真实输入工作

构建缓存用于复用条件相同的步骤。常变化的内容过早进入构建流程，可能使后面的步骤频繁重新执行；为了追求缓存而遗漏必要输入，又可能产生与源码不一致的产物。先确定正确输入，再观察哪些步骤可以复用，顺序不能倒过来。

本节不提供固定公共基础镜像版本，因为需要由使用者按项目兼容性和审核结果选择。记录基础镜像身份、构建命令与产物摘要，比在文章里写一个会过期的“最新”标签更有意义。标签与不可变身份也需要在交付记录中区分。

## 自己检查

从树形结构列出哪些文件应该进入最终镜像、哪些只参与构建、哪些完全不该进入上下文。增加一个假的 `.env.example-private` 文件，检查忽略规则是否符合预期；文件中不要放真实值。当前环境没有Docker，本篇未执行镜像构建。上下文及忽略规则的完整语义参见 [Docker 构建上下文文档](https://docs.docker.com/build/concepts/context/)。

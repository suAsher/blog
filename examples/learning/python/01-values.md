## 把输入和判断分别写清楚

下面的数据只存在于代码中。运行后会打印两个队列的判断结果，我们先用最小规则练习类型与控制流，不读取实际服务配置。Python 不要求每个变量声明静态类型，但每个运行中的对象仍有类型，操作也有相应约束；字符串中的数字不会因为看起来相同就自动变成整数。

```python
queues = [{"name": "small", "waiting": "2"}, {"name": "busy", "waiting": "12"}]
limit = 8

for queue in queues:
    waiting = int(queue["waiting"])
    if waiting < 0:
        raise ValueError("waiting must be non-negative")
    overloaded = waiting > limit
    print(queue["name"], waiting, overloaded)
```

输出为 `small 2 False` 和 `busy 12 True`。`int` 是一次显式转换，`>` 比较数值，`if` 根据布尔条件决定分支。把输入改成 `"unknown"`，转换会失败；这种失败说明输入没有满足程序的约定，不应该靠把它替换成零来隐藏。零是一个有效的业务值，不能同时承担“未知”的含义。

## 容器帮助组织数据，不能替你建立规则

列表保留本例中的处理顺序，字典把字段名关联到值。遍历列表时，`queue` 是本次取出的元素，不是自动生成的新副本；修改字典可能影响调用方仍在使用的对象。入门练习可以先避免修改输入，生成新的结果对象，把输入事实与输出判断分开。需要复制时，也要分清浅拷贝和嵌套对象仍被共享的情况。

## 验证边界，而不只验证快乐路径

加入等待数为 `8` 的样本，确认本例采用“严格大于上限”而不是“大于等于”。再加入负数，确认校验抛出错误。把这两个约定写在代码旁边，后续修改上限时才能知道行为是否有意改变。输出顺序在这里由列表决定，不应将其他来源的无序概念偷偷带进来。

## 刚保存的内容，换一处却还是旧的

文章保存成功以后，列表可能从另一份副本读取。如果副本还没有应用新版本，读者就会看到旧摘要。是否允许短暂旧值取决于具体操作：浏览历史归档或许可以接受，确认刚发布的标题则往往需要更明确的保证。先描述用户刚完成了什么，再选择读取约定，比直接宣称“强一致”更容易检验。

这里用单一写入者生成的递增版本号模拟文章副本。读取可以携带最低版本；副本未追上时明确拒绝返回陈旧结果。真实服务可以选择等待有限时间、路由到已满足要求的位置，或返回可重试状态。本例选择立即报错，强调不能把旧值伪装成刚保存的版本。

```python
def read_at_least(replica, minimum):
    if replica['version'] < minimum:
        raise LookupError('replica not ready')
    return dict(replica)

replica = {'version': 4, 'title': 'old'}
try:
    read_at_least(replica, 5)
except LookupError:
    pass
else:
    raise AssertionError('stale result accepted')
replica = {'version': 5, 'title': 'new'}
assert read_at_least(replica, 5)['title'] == 'new'
print('version 5 is visible')
```

预期输出 `version 5 is visible`。练习写出三种界面的最低要求：随便浏览、保存后确认、执行依赖新值的下一步。并不是每次请求都要等待最新版本；更严格的要求可能增加等待和故障时的拒绝率。把这些体验成本记录下来，才有可讨论的取舍。

## 数字不是完整的一致性协议

本例版本号只有在单一权威分配、同一对象内比较时才有意义。多主写入可能需要其他冲突表达，机器时间也不能直接充当可靠提交序号。读到版本五不会证明跨对象事务成立，更不能证明一个副本永远不会回退。设计接口时应说明对象范围、成功响应的含义和失败恢复动作；本节只提供识别陈旧结果的最小练习，不实现复制、选主或共识算法。

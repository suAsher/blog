## 一份账本，先只有一个写入者

假设一个练习账户初始有一百分。先收到加二十分，再收到减三十分，结果应是九十分。这个例子故意不涉及网络：如果单进程里都无法解释余额如何改变，把它放到多台机器上只会增加排查难度。学习的第一步是区分状态与动作，余额是状态，加减分是输入；一次输入能否接受，要由明确规则判断。

下面把状态转移写成纯函数。它返回新余额，不修改调用方的字典。扣减不能使余额为负，这是本例的不变量。执行顺序也属于约定：先扣一百一十分再加二十分，与先加后扣并不等价，因为中间动作可能被拒绝。这里选择对非法动作立即报错，避免把失败伪装成没有发生变化。

```python
def apply(balance, delta):
    if not isinstance(delta, int):
        raise ValueError('integer delta required')
    result = balance + delta
    if result < 0:
        raise ValueError('insufficient balance')
    return result

balance = 100
for delta in [20, -30]:
    balance = apply(balance, delta)
assert balance == 90
try:
    apply(balance, -100)
except ValueError:
    pass
else:
    raise AssertionError('invalid debit accepted')
print(balance)
```

运行应输出 `90`。断言验证的是算术和拒绝规则，并没有证明真实金融系统安全。试着把动作顺序颠倒，再加入一次足以触发余额不足的扣减。记录被拒绝的动作是否还需要审计、重试时是否会重复扣分，这些问题将自然引出事件记录与幂等。

## 把单机边界带到下一节

这个函数没有处理多个写入者、持久化、进程崩溃或时钟。如果两台机器都从同一个旧余额计算新值，最后直接覆盖文件就可能丢失一次更新。解决前先决定谁有权写入、如何识别同一条命令、结果何时算提交。不要把“使用一个字典”误认为数据库事务；本节留下的是可检查的业务规则，而不是存储方案。

## 先算清一块数据占多少字节

假设一个练习张量的形状为两条样本、每条八个位置、每个位置十六个数值。每个数值按两个字节存储，那么元素数量和存储字节数如下。这里没有导入深度学习库，也不会申请 GPU；我们只检查预算公式的单位是否自洽。

```python
from math import prod

shape = (2, 8, 16)
bytes_per_element = 2
elements = prod(shape)
storage_bytes = elements * bytes_per_element
assert elements == 256
assert storage_bytes == 512
print(f"{elements} elements, {storage_bytes} bytes")

```

运行后应输出 `256 elements, 512 bytes`。不要把这个数字称为 Python 对象实际内存。列表、整数对象和解释器有额外开销；这里也没有构造真实浮点张量。公式描述的是指定布局下的数据载荷，学习目的在于区分“元素数”和“字节数”。

## 给每一个维度命名

形状中的每个轴应写进文档，而不是留下一串无法解释的数字。批大小、序列位置和隐藏维度代表不同的增长方向。增加批大小可能提高并行机会，也会同时增加需要保存的数据；增加输入长度则可能改变计算、缓存和调度的压力。不要把某个维度翻倍直接等价为整体延迟翻倍，执行路径不只取决于元素数量。

精度也要使用明确单位。两个字节只是本例选择的存储假设，不保证所有计算中间值都使用相同类型。真实运行时还可能有对齐、打包、临时缓冲与类型转换；一个纸面公式不等于设备上可分配的连续内存。

## 把估算和测量分开保存

建议记录三栏：输入假设、计算结果、需要实测的未知项。例如本例的轴含义与每元素字节数属于假设，五百一十二字节是推导结果，实际分配器开销则是未知项。清楚标记后，未来替换模型或运行时不会把旧估计误认为新事实。

将位置数量从八改为十六，先手算再改断言。再分别用一字节和四字节重算，解释为什么元素数量保持不变。最后尝试负数维度，补充输入校验；数学乘积能够算出结果，不代表它描述了合法的张量。

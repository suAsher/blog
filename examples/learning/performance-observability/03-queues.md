## 每秒处理四个，为什么越来越慢

构造一个离散模型：每轮到达六个任务，处理能力只有四个。处理端每轮都忙，完成数看起来也很稳定，但等待队列每轮增加两个。只盯着吞吐曲线，可能看不到用户等待正在恶化。到达率、完成率和队列长度必须一起观察；其中任何一个指标单独变好，都不必然代表整体体验改善。

下面约定每轮先接收新任务，再处理最多四个，队列用整数表示，不模拟单个任务的真实执行时间。明确轮次规则很重要：不同的先后次序会影响首轮观察，但不会改变持续超载时积压增加的事实。所有数字都是教学输入，不是容量压测结果。

```python
queue = 0
completed = 0
history = []
for arrivals in [6, 6, 6, 6, 6]:
    available = queue + arrivals
    served = min(available, 4)
    queue = available - served
    completed += served
    history.append(queue)
assert completed == 20
assert history == [2, 4, 6, 8, 10]
print(history)
```

运行输出 `[2, 4, 6, 8, 10]`。练习把到达序列改成先突发、后空闲，观察队列何时排空；再加入最大队列长度，统计被拒绝的任务。限流、背压和拒绝通常意味着主动选择边界，不应把拒绝数藏起来当作系统更快的证据。

## 公式要带着假设使用

在满足稳定等条件的系统中，长期平均在途量、到达率和停留时间可以建立联系，但不能把这个关系直接套到一直增长的瞬态队列上。本节只用守恒关系核对进入、完成与剩余，没有实现精确排队理论模型。真实服务还会受到任务大小、优先级、资源竞争和重试影响。出现高延迟时，先区分等待变长还是执行变慢，再决定测量哪一层；直接增加并发可能把瓶颈推向下游。

## 性能与规模边界

Lighthouse 13.5.0 / Chrome 156.0.8078.80，30 篇生成文档，每页、每设备三个独立冷浏览器样本，完整记录见 [performance.json](performance.json)。

| 页面 | 手机性能中位数 / 最低 | 手机 LCP 中位数 / 最慢 | 桌面性能 |
| --- | --- | --- | --- |
| 首页 | 98 / 98 | 2117 / 2121 ms | 100 |
| 收件箱 | 99 / 99 | 1962 / 1962 ms | 100 |
| 段落搜索结果 | 99 / 99 | 1666 / 1670 ms | 100 |

所有样本的无障碍和最佳实践分数均为 100；首页达到 2.5 秒 LCP 预算。这些结果来自回环 HTTPS 与真实 Go 鉴权，不代表公网、物理手机或服务器高负载保证。没有重复测量历史长文页面，不用历史成绩替代本轮证据。

Vitest 覆盖率只对应配置中选定的库，不代表全部 DOM 脚本；DOM 交互由浏览器用例补充。收件箱沿用既有全库元数据扫描，大规模资料库的性能尚未验证。段落搜索有显式扫描与缓存预算，达到预算会显示部分结果。长期删除文档留下的整理状态在下次成功批量操作时安全清理，保留垃圾箱条目；孤儿额度释放及失败不部分写入有 Go 回归测试。

```bash

node --check scripts/showcase-workflow-v3.mjs
node scripts/showcase-workflow-v3.mjs
BLOG_PERF_PATHS='/,/inbox/,/search/?q=性能' \
  BLOG_PERF_OUTPUT=docs/qa/workflow-v3/performance.json \

```

截图、完整端到端测试和 Lighthouse 应顺序执行，避免 CPU、浏览器与端口资源争用。脚本只启动自己在本机 4493 端口的临时服务，使用当前 `dist/` 的冻结副本，并在结束后清理进程、随机凭据和临时内容。产物仅包含生成资料截图与聚合检查，不保存 Cookie、凭据或请求原始记录。

# Wiki 链接与知识图谱

知识连接复用现有 Markdown 文档和发布快照。阅读页、反向链接与默认图谱只展示已发布内容；写作补全可以查找工作稿，不会因此把草稿关系提前公开到阅读视图。

## 写下连接

```markdown
这段想法接着 [[一个概念]] 继续展开。
也可以使用 [[一个概念|更贴合上下文的文字]]。
```

在编辑器输入 `[[` 后可查找文档，用方向键选择、Enter 插入、Escape 关闭；输入法组合输入期间不抢占按键。补全使用稳定文档 ID，显示文字仍是标题：

```markdown
[[文档ID|显示标题]]
```

这类链接在目标改名后仍能指向同一篇文档。手写标题链接先匹配唯一的当前标题，再尝试标题历史；出现多个同名目标时明确标为歧义，不随机选择第一篇。若旧标题被另一篇文档重新使用，当前标题优先，因此长期引用建议使用编辑补全插入的稳定链接。

未创建的目标可以进入带标题的新建草稿入口。草稿仍需明确发布后才进入正式阅读。代码围栏与行内代码中的 `[[...]]` 保留字面内容，不产生链接；不支持把 Wiki 语法当作任意 HTML 或脚本执行。

## 发布与标题历史

工作稿和发布快照分别保留标题历史，最多各 32 个并受字节预算限制。修改工作稿标题不会立即改变正式阅读中的目标名称或解析关系；再次发布后才更新发布视图。

历史从本版本开始记录，不能还原旧版本未保存的历次改名。完整搬迁空间时请备份整个内容目录以保留文档 ID；单篇 Markdown 导出仍保留 Wiki 源码，跨实例重新导入时需核对其中的稳定 ID 引用。

图片相对路径映射和标题历史是不同字段。导入的配图仍沿用原路径与哈希资源，不会被标题改名影响。

## 反向链接和图谱

文章底部的反向链接展示哪些已发布文档引用了当前文章。图谱连线来自显式 Wiki 引用和 `related` 关联；标签用于颜色和筛选，不会凭相似标签编造引用关系。

图谱最多显示 300 个节点，并明确提示是否截断。可通过节点列表使用键盘打开文章，搜索标题，并使用缩放/重置控件；画布支持拖动与节点选择。减少动画模式使用静态布局，隐藏标签页或图谱离开视口时暂停计算。

## 预算与失败行为

- 单篇最多解析 256 个 Wiki 链接，超出部分保留原文字面内容。
- 派生链接索引最多 4 MiB，与搜索缓存共同考虑小型云服务器内存预算。
- 图谱连线总量不超过 `min(2400, 节点上限 × 8)`；反向链接最多返回 300 篇，接口保留总量和截断标记。文档补全查询最多 256 个 Unicode 字符。
- 索引超预算时，图谱和连接接口返回明确的暂不可用错误，正文与保存流程仍可用；不会把索引失败伪装成文档保存失败。
- 索引不是真实文档存储，可在内容更新后失效并重建，重启不需要恢复数据库。

备份整个 `data/content/` 保留 Markdown、发布快照、配图和标题历史。回滚后端前先验证新增字段的读取与写入兼容性，避免旧程序保存时丢弃标题历史。

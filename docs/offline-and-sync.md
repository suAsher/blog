# 离线阅读与跨设备同步

知识空间只有一个空间所有者账号，整站默认私有。这里的“阅读状态同步”和“离线阅读”是两套独立机制：前者同步收藏、已读、进度与回顾计划；后者在用户明确同意后，把少量已发布快照加密保存在当前设备。两者都不是多人协作，也不能替代服务端内容备份。

## 阅读状态如何同步

收藏、已读、进度和回顾计划仍先写入浏览器的 `asher-reading-v1`，页面离线时可以继续使用。登录并联网后，浏览器把变更写入本地待同步队列，再以字段级版本进行比较并同步到服务器；进度类网络写入最多每 10 秒合并一次。首次接入同步时，只会把服务器字段版本仍为 `0` 的本机非默认值迁移上去，避免用旧浏览器状态覆盖已有服务器记录。

同一字段已在另一设备变化时不会按设备时间“最后写入者获胜”。界面会显示冲突，由所有者选择“保留服务器”或“重新应用本机”。普通网络失败和会话过期 `401` 都会保留本地待同步队列，重新登录后继续发送；队列无法持久化时页面会明确警告，应保持页面打开并从书架导出记录。

多标签页协调依赖 Web Locks API，避免两个标签页用不安全的 localStorage 竞争覆盖。浏览器不支持该 API 时会停止服务器同步、安全降级为仅本机记录，并显示可见警告。

服务端使用自己的时钟安排回顾：启用后依次在 1、3、7、30 天后到期，之后保持 30 天间隔。设备时钟只用于本地界面和离线快照期限，不能直接覆盖服务器状态。

服务端状态位于 `data/content/state/reading.json`，目录权限应为 `0700`、文件为 `0600`。存储上限为 10000 篇、4 MiB；每批最多 32 个操作、32 KiB，请求回执最多保留 256 个。它与文档共用单个 Go 进程的写锁和原子换名写入；部署只运行一个写入该内容目录的 auth 实例，不要把共享目录同时挂到多个写入者。它没有数据库，备份整个 `data/content/` 即同时包含文档、配图、活动和服务端阅读状态。

## 导出、退出与会话过期

书架的 v1 JSON 导出结构仍是 `{ version: 1, exportedAt, entries }`。核心字段为收藏、已读、进度和更新时间，条目可带回顾计划；文件不包含文章正文、离线正文、图片、登录密码、Cookie 或同步协议的待处理操作。导入先合并到本机，再走正常的字段冲突处理；它不能绕过服务器版本直接覆盖另一设备的新操作。

回顾计划导入同步的是启用/停用意图，阶段与日期由服务器重新安排，不把旧设备的时间直接写回。要完整恢复服务端回顾日程，请恢复内容备份中的 `state/reading.json`。

明确点击“退出登录”时，本机锁定和清理会在等待网络确认之前立即开始；随后浏览器请求撤销服务端会话。即使退出响应丢失，设备也先保持锁定并提示服务器尚未确认。清理会删除加密离线库和阅读同步协议元数据；`asher-reading-v1` 书架记录和主题仍保留。普通 `401` 会锁定并清除离线库，但保留阅读同步待处理队列，供重新登录后续传。若本机清理只能部分完成，页面保持锁定，并在登录页显示清理未完成警告；此时按提示清除该站点数据或重新登录后重试。

## 主动保存加密离线快照

只有已发布文章出现“保存离线”。第一次使用时需明确同意限制，并设置独立于站点登录密码的本地口令，至少 10 个字符。密钥由 PBKDF2-SHA256 派生，正文、标题、标签、目录和配图使用 AES-256-GCM 加密后写入 IndexedDB；派生密钥只保存在内存，不把口令、服务器密码或会话写入 IndexedDB。

IndexedDB 的明文索引只保留不含正文的最小头信息：不透明文档 ID、版本计数、保存/到期时间、密文大小和 IV。这里的版本只是用于失效判断的非内容计数，不是标题或正文。密文、随机盐和口令校验密文也不是可阅读文章数据。

离线库有固定预算：

- 每台设备最多 20 篇、总计 50 MiB；单篇加密包最多 16 MiB、最多 32 张配图。
- 每份快照保存 7 天，到期判断依赖设备时钟；到期后需联网重新保存。
- 只保存服务器返回 `200` 的已发布投影，不保存工作稿。原始 API 响应不会进入 Cache Storage。
- 离线库不是服务器备份。忘记本地口令后无法恢复这份加密副本；清除它，重新联网并从服务器保存即可。

锁定按钮会通知同源其他标签页一起丢弃内存密钥；离开页面的 `pagehide` 只锁定当前标签页的密钥。远端撤回、删除或改版无法即时触达一台真正离线的设备，所以不要把离线副本交给不受信任的设备。

恢复联网后，浏览器用已认证的 `GET /api/offline-revisions` 分批检查 1–20 个 ID。接口只返回 ID、是否仍可用和小型版本元数据；删除、撤回或版本变化会使本地副本失效，未发布的草稿更新也可能保守地使它失效。在线检查收到 `401`、`403` 或认证重定向时会清除整个离线库。

## Service Worker 与安装边界

Service Worker 的精确白名单只包含无正文的 `/offline/` 外壳、manifest、图标和构建生成的安全哈希依赖。它从不缓存登录页、`/auth/*`、`/api/*`、私有文章 HTML 或搜索索引；导航在线时以网络响应为准，只有网络真正失败才回退到离线外壳。manifest 以 `crossorigin="use-credentials"` 获取，不扩大 Caddy 的匿名登录资源白名单。

安装和 Web Crypto 需要 HTTPS（本机安全上下文除外）。点击“安装应用”后，支持的浏览器会给出真实安装提示；没有提示时按页面说明使用浏览器菜单或“添加到主屏幕”。已安装应用的“随手记”快捷方式打开 `/?capture=1`，只携带动作标记，不携带笔记正文。

更新不会在后台自动刷新正在编辑的页面。只有用户选择“应用更新/刷新应用”并且未保存内容的保护检查通过后才重新载入；保存失败或超时会取消更新。

## 维护与故障处理

- 忘记离线口令：清除此设备离线资料，联网登录后重新保存；服务器文章不受影响。
- 远端文章已撤回但设备仍离线：副本可能在 7 天期限内继续可读；设备联网验证后才会删除。
- 退出后提示清理不完整：不要继续解锁旧资料，按登录页提示清除站点数据或关闭其他标签页后重试。
- 更换设备：阅读记录可登录后同步或用 v1 JSON 迁移；加密离线库不会上传服务器，也不会自动迁移。
- 备份与恢复：备份整个服务端 `data/content/`；浏览器离线库仅是可重建副本，不应放入服务端备份流程。

部署时保持 HTTPS、Caddy 精确登录白名单、私有 API 鉴权和 `Cache-Control: no-store`。项目不依赖 CDN 或在线字体。本轮 Lighthouse/LCP 实测与环境边界见[性能记录](qa/performance.md)和[验证记录](qa/verification.md)；这些是本地受控结果。

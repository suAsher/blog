# 文档写作、导入与备份

这个空间保持私有，阅读和写作都需要登录。正式内容由服务器保存；首页、文章列表和搜索默认只展示已发布文档。无内容时显示写作和导入入口，原静态示例仅在主动选择「查看示例」时展示。

## 站内写作

1. 登录后打开「写作」，或访问 `/manage/`，点击「新建文档」。
2. 填写标题，使用 Markdown 编辑正文；「文档信息」可设置摘要、标签、可选分类、日期和封面。标签与分类来自你的内容，没有固定技术领域。
3. 输入会自动保存工作稿。离开或关闭页面前确认「所有修改已保存」，也可用 `Ctrl/Cmd + S` 或「保存」。
4. 使用「对照预览」或「预览」检查排版。代码块、表格、引用、标题与图片采用和正式阅读相同的安全 Markdown 渲染。
5. 点击「发布文档」。发布后立即进入首页、列表、全文搜索与阅读页，无需重新构建或部署网站。

图片通过编辑器「图片」按钮上传并插入 Markdown；「上传封面图片」可设置封面。支持 PNG、JPEG、GIF、WebP，单图最大 8 MiB；不接受 SVG，需先转为受支持的图片格式。

已发布文档继续编辑时，只更新工作稿，阅读页仍显示最近一次发布快照。确认修改后再次点击「发布文档」。当前保留工作稿与最近发布快照，定期备份用于恢复更早内容。

## 草稿、撤回与垃圾箱

- 草稿只在写作空间出现，不进入首页、文章列表或正式全文搜索。
- 「撤回发布」将文档变回草稿，原阅读地址不再返回正文；内容仍可编辑和重新发布。
- 「移入垃圾箱」是软删除。垃圾箱中可「恢复为草稿」，检查后再发布。
- 「永久删除」仅对垃圾箱文档可用，操作前先导出需要保留的内容。
- 删除文档不会自动删除全部配图，避免破坏其他文档引用同一哈希图片。空间紧张时应扩容或先审阅备份和资产引用，不使用全局 Docker prune 或直接删除 `assets/`。

文档地址使用稳定随机 ID；修改标题不会改变地址。程序升级或认证服务重启会要求重新登录，但正式文档位于独立持久卷中，不会随会话退出而丢失。

## 从本机批量导入

只上传你在页面里主动选择的文件，系统不扫描本机目录。打开「导入文档」后可选择多个文件、选择文件夹，或拖入文件。存在配图时优先选择文件夹，这样浏览器能保留原相对路径。

例如选择整个 `笔记库` 文件夹：

```text
笔记库/
  docs/
    阅读记录.md
  images/
    图表 1.png
```

正文中的标准 Markdown 图片引用：

```markdown
![一次观察](../images/图表%201.png)
```

导入会把所选目录里的图片关联到文档；不会按错误相对路径静默使用其他目录同名图片。单独平铺选择文件无法提供完整目录结构，若系统使用唯一文件名兜底会报告警告。没有匹配到的配图会列出原引用路径，便于你重新选择正确目录，或在编辑器上传图片并替换链接。服务器不抓取远程图片；外部图片地址也不能代替本地配图备份。

### 支持格式与边界

| 内容 | 支持与限制 |
| --- | --- |
| 文档 | UTF-8 的 `.md`、`.markdown`、`.txt`；单篇正文最多 2 MiB |
| 解析复杂度 | 非代码行最多 10000 行、结构标记最多 20000 个、引用嵌套最多 32 层；过于复杂的文档需拆分 |
| 图片 | PNG、JPEG、GIF、WebP；单张最多 8 MiB，并检查真实格式与尺寸 |
| 一批上传 | 最多 32 MiB、500 个文件；接近上限时分批并留出上传封装余量 |
| 不接受 | SVG、Word、PDF、压缩包、可执行文件；隐藏或可能包含凭据的文件会跳过或拒绝 |
| 服务器容量 | 写入至少保留 64 MiB 空闲空间，并为在途上传预留容量；不足时明确报错 |

导入界面先列出文档数、图片数、体积和跳过项。点击「导入为草稿」后，结果会分别列出成功文档、跳过文件、警告与未匹配图片。不要只看成功数量就发布；先打开草稿检查正文与配图。部分文件被跳过时，其原因在报告中说明，不会静默覆盖现有文档。

标准 Markdown 的标题、列表、表格、引用、围栏代码块和相对图片路径均可导入。长代码块与纯文本仍受单篇 2 MiB 大小限制；复杂度检查在解析与落盘前执行，避免异常嵌套占满小服务器资源。只有主动选择的文件会被上传，缺失配图会报告原路径，服务器不扫描本机或下载远程资源。

### Markdown 元数据

Markdown 可使用 YAML frontmatter：

```markdown
---
title: "一次阅读记录"
description: "这篇笔记记录一个问题和验证过程。"
date: 2026-10-25
tags:
  - 阅读笔记
  - 待验证
category: "个人笔记"
cover: "../images/图表%201.png"
---

## 一个值得追问的问题

正文从这里开始。
```

支持标题、摘要（`description`，也识别 `summary`）、日期、标签、分类和封面。没有标题时可从首个一级标题或文件名推导；摘要为空时从正文生成。没有元数据的 Markdown 和 TXT 也可导入，之后在写作空间补充。原始 HTML 不执行，脚本和不安全链接不会成为可运行内容。

## 保存失败与多窗口冲突

断网、服务器容量不足或请求失败时，界面会显示保存失败，并保留当前输入。不要立即关闭标签页；可以重新保存，或选择「下载当前未保存原文」。当前标签页还会尝试保留未保存备份，但这不是持久备份。

如果同一文档在另一个窗口已更新，服务器返回版本冲突。当前窗口不会覆盖新版本：先下载本页原文，再「重新加载服务器版本」，比较并合并需要保留的修改。不要把刷新页面当作保存成功。

## 导出与迁移

「导出 .md」下载包含 YAML 元数据和当前工作稿的标准 Markdown。单独 `.md` 文件不携带配图；要离线阅读、迁移或保留目录引用，使用「打包导出」，下载正文和配图的 ZIP。导出的 ZIP 保留安全的可解析路径，不包含服务器凭据、会话或其他文档。

个人文档的导出用于交换与逐篇备份；完整恢复仍需要服务端内容备份。正文、配图和发布状态保存在服务器；浏览器的收藏、已读与阅读位置在「我的书架」另行导出 JSON，不会自动跨设备同步。

## 备份与恢复

### 需要备份什么

正式部署使用以下三类数据，分别保管：

1. **程序源码**：本项目、锁文件、部署示例，可重建程序和界面。普通源码归档排除 `data/`、`gateway/`、`secrets/` 和私有运行文件。
2. **服务端私有数据**：`/srv/asher-knowledge/data/content/` 中的文档记录与配图，以及 `gateway/` 的密码验证器、证书、程序、配置和 `secrets/` 的访问记录。单独加密备份，不能放进公开仓库或普通源码包。
3. **浏览器记录**：在「我的书架」导出阅读记录 JSON。服务器备份不包含这些浏览器状态。

`data/content/documents/` 的 JSON 保留 Markdown 原文、元数据、当前工作稿和发布快照；`assets/` 保存哈希图片；`tmp/` 只用于导入暂存。不要只备份 `dist/` 或旧 `src/content/articles/`：前者是页面外壳，后者是静态示例，不包含站内新增文档。

### 创建一致的加密备份

为避免备份时跨越正在进行的草稿更新或导入，选择短暂维护窗口，停止本博客的 `auth` 和 `gateway`，完成后立即启动。其他网站容器不需要停止。停用或重建认证服务会使会话失效，恢复后重新登录。

建议在自己的电脑通过 SSH 流式接收并加密，避免在已经紧张的服务器磁盘上再写一份备份。把 `YOUR_SERVER` 替换为自己的 SSH Host 别名或 `your-user@your-server`。下面示例需要本机安装 GnuPG；密码通过交互式提示输入，不放进命令参数。归档可能包含文档、密码验证器、证书私钥和登录信息，应保存到受控备份介质。

```bash
ssh YOUR_SERVER 'cd /srv/asher-knowledge/gateway && docker compose --env-file runtime.env -f compose.yaml -f compose.http.yaml -f compose.session.yaml stop auth gateway'
ssh YOUR_SERVER 'tar --numeric-owner -czf - -C /srv/asher-knowledge data/content gateway secrets runtime.env' | gpg --symmetric --cipher-algo AES256 --output asher-private-backup.tar.gz.gpg
ssh YOUR_SERVER 'cd /srv/asher-knowledge/gateway && docker compose --env-file runtime.env -f compose.yaml -f compose.http.yaml -f compose.session.yaml up -d --no-build --pull never --wait auth gateway'
```

检查备份命令退出状态和文件大小；无论备份是否成功，都确认服务已重新启动并检查健康状态。可在自己的电脑用 `gpg --decrypt asher-private-backup.tar.gz.gpg | tar -tzf -` 检查目录清单，不要将解密内容或密码输出到公开日志。保留多个日期的备份，并定期在独立恢复目录验证可读性。

### 恢复与程序回滚

恢复前先保留当前数据快照；不要把旧备份直接覆盖到仍在写作的服务。先停写，在独立恢复目录解密检查，再恢复到目标部署目录。保持内容目录 UID/GID `101:101`、`0700`，验证器 root:101、`0440`，Caddy 证书数据 UID/GID `1000:1000`、`0700`；按归档保留子文件的权限。

恢复顺序：程序和三份 Compose 配置 → 密码验证器、内容持久目录与证书数据 → 私有网桥/HTTP-01 路由检查 → 启动 `auth` 等待健康 → 验证并启动网关 → 登录检查草稿、发布快照和配图。换服务器时还需检查 HTTPS IP、Origin 和证书配置，不能只复制旧 IP 的验证器后直接访问。

程序回滚与内容恢复是两件事。切回旧程序时保留同一个 `data/content/`，先确认旧程序兼容当前文件格式；不能为回滚界面而把新文档换成旧数据。内存会话无需备份，恢复后重新登录即可。

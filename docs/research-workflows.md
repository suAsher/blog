# 从导入到自己的研究笔记

本轮新增导入预检、文档历史、段落批注与专题工作区。仍为单所有者私有空间，所有数据接口需要登录；不依赖数据库、在线字体或外部 AI 服务。小于 768px 的首页默认使用轻量 CSS 星轨，保留暂停、减少动画和离屏停止；较大屏幕满足能力预算时继续加载 WebGL 星云，阅读与写作使用原生滚动。

## 导入前先检查

打开「写作 → 导入文档」，选择 Markdown、TXT 与配套图片，界面会自动向服务器请求预检。预检只使用临时文件，结束后清理，不会创建文章或永久图片。

预检显示解析后的标题、原路径、重复或变更候选、缺失配图及跳过原因：

- **新文档**：默认创建草稿。
- **内容相同**：默认跳过；需要独立副本时，明确选择创建副本。
- **已有文档有变化**：默认跳过。可选择更新已有工作稿，或创建副本。
- **无效文档**：显示原因，不提交为文章。

更新工作稿使用预检得到的文档版本。另一窗口已修改时，服务器拒绝覆盖，请保留所选文件、重新预检后核对。更新不会改变线上发布快照，也不会把新配图映射提前带入旧快照。

确认后会重新上传所选文件并复核。请求标识用于重试恢复，服务器保留最近 20 份、合计最多 8 MiB 的导入报告；每篇记录保留最近一次导入回执用于中断恢复。它们不是无限期幂等日志，也不能替代内容备份。报告可在「查看最近导入报告」重新打开，并跳转成功导入或更新的文档。

仍保留每批 32 MiB / 500 文件、单篇 2 MiB、单图 8 MiB 的限制；新预检一批最多核对 1000 个不同配图引用，引用路径最多 2048 字节。现有文档扫描最多 10000 文件、累计 128 MiB，超额会明确提示，不返回不完整的去重结果。大资料库应分批整理和评估容量。

## 历史版本与发布对照

编辑器「历史版本」会先保存当前编辑，再列出旧快照。可查看标题、文档信息与 Markdown 增删差异，或将旧快照恢复为新的工作稿。恢复操作需要当前版本一致；不会覆盖另一窗口修改。

每篇最多保留 12 个旧快照，序列化历史合计最多 6 MiB。达到任一上限时删除最早快照；接近 2 MiB 的长文能保留的份数会更少。无变化自动保存不添加快照。上线此功能之前的历史无法凭空补回，旧文档仍正常读取，在后续修改时开始积累。

历史与正文在同一私有记录内原子提交，图片映射也随快照保留。永久删除文档会一并删除该记录中的历史；共享图片仍遵循原资产保留规则。

已经发布的文章再次发布前会显示工作稿与线上版本对照。仅改变配图映射、链接解析等渲染结果时，也会提示核对，不会误称完全没有变化。文字差异视图有预算：前 10000 行、最多展示 400 行、每项最多 2000 字符；超出时明确提示，完整 Markdown 可导出检查。

## 在阅读中留下批注

正式文章正文选中 1–2000 字后，点击「批注选中文字」。可填写最多 8000 字的想法并选择薄荷、紫藤或琥珀色。批注保存到服务器，刷新和换设备后可以读取；示例静态路由与离线正文不提供此服务端功能。

定位使用原文片段、前文和后文，而不是单纯依赖字符位置。只有唯一可靠匹配才高亮或跳转；原文变化、缺失或匹配不唯一时，保留摘录并显示待核对，不会强行绑定另一段。浏览器不支持 CSS Highlights 时仍可通过列表定位阅读。

「摘录为新笔记」创建真实随手记草稿，包含摘录、批注和来源深链；不会自动发布。批注内容按普通文字显示，HTML 不会执行。另一处修改时提示版本冲突并保留输入，重新读取不会静默覆盖正在输入的正文。

每篇最多 200 条，空间合计最多 1000 条批注；单次创建/编辑请求最多 64 KiB。草稿、撤回和垃圾箱里的批注不会在正式阅读接口返回。已知标识的批注仍可按版本删除；新建批注时会回收确认已永久删除文档的孤立记录，草稿和垃圾箱文档的批注保留。

## 专题工作区

导航「专题」或命令面板搜索「专题工作台」进入。点击「新建主题」，填写问题背景，按标题搜索并加入已有文章或草稿，安排顺序，再点击「保存主题」。

- **阅读路径**：通过上移/下移按钮排序。草稿明确标记并跳转写作；正式阅读使用已发布标题和快照。
- **问题清单**：记录待验证问题、完成或删除项目，状态随主题保存。
- **文章对照**：从主题内选择两篇已发布文章独立阅读。工作稿和未发布修改不进入对照；手机改为纵向排列。
- **连接画布**：连线表示安排的阅读顺序。拖动卡片，或聚焦后使用方向键移动，Shift 加速；移动使用 transform。位置在保存主题后持久化，画布不执行用户代码。

文章撤回或删除时，主题保留失效引用并显示不可用；仍可修改主题说明或问题，也可明确移除该引用。新加入的引用必须是存在且不在垃圾箱中的文档。

主题采用版本冲突检查。冲突时本地编辑保留，可明确选择放弃并读取最新版本，或核对后重新应用到最新版本；不会按设备时间静默覆盖。离开有未保存修改的页面会提示。

空间最多 50 个主题，每个最多 100 篇文档、50 个问题；请求最多 128 KiB。研究状态文件合计最多 16 MiB，0600 权限、原子写入；损坏、权限异常或符号链接会拒绝读取。

## 示例与备份

[工程研究演示包](../examples/research/README.md)提供 4 篇 Markdown、1 篇 TXT、2 张原创 PNG；另有站内写作示例正文。标题和正文明确标注生成演示，场景、数字和图表不代表真实经历或测量结果。导入真实资料仍需你主动选择文件，本程序不会扫描本机目录。

开发环境可在构建后运行以下命令复现上传、站内写作、批注和专题，并生成三个尺寸、深浅主题的截图：

```sh
node scripts/generate-research-examples.mjs --check
node scripts/showcase-research.mjs
```

第二个脚本使用独立本机 HTTPS、临时账号及内容目录，结束后清理；不会连接云服务器或读取部署凭据。需要 Go 1.26 与已安装 Chrome，输出位于 `docs/qa/research/`。

需要在自己的已部署空间中保留同一组示例时，先运行无凭据的检查：

```sh
python3 deploy/seed-research-demo.py --examples examples/research --dry-run
```

随后仅在服务器上执行，凭据始终留在服务器内存中：

```sh
python3 /srv/asher-knowledge/current/deploy/seed-research-demo.py \
  --examples /srv/asher-knowledge/current/examples/research \
  --server-root /srv/asher-knowledge
```

它通过真实 HTTPS API 预检和上传资料包，创建站内写作示例、草稿、批注与专题；不会直接改写内容 JSON，也不会覆盖已有文档。成功后在服务根目录 `showcases/` 留下 0600 的示例标识，重复运行保留已有结果。该标识属于运维元数据，也应随服务器配置备份；不要把服务器凭据或真实文章归档到公开仓库。

服务器备份仍需覆盖完整 `data/content/`：`documents/` 包含正文与有限历史，`assets/` 包含配图，`state/import-reports.json` 保存导入报告，`state/research.json` 保存批注和主题，`state/reading.json` 保存阅读同步。备份应短暂停止唯一写入者以保证一致性，并验证恢复。单篇 Markdown/ZIP 导出不包含全站主题、批注或所有历史。

更新先部署兼容新字段的 Go 服务，再部署静态前端。新字段写入后，不应直接让旧 Go 服务重新保存这些记录。回滚界面可以保留新后端与内容卷，任何程序回滚都不能覆盖部署后的新文章。
